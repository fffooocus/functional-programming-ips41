# Лабораторна робота №2

**Левківський Євгеній Сергійович · ІПС-41**

Перше завдання: багатопотокове стиснення множини файлів в один архів алгоритмом Хаффмана та вимірювання ефективності.

```powershell
.\.build\lab2.exe pack 4 lab2/demo.hfar lab3/examples/textbook.txt lab1/README.md +RTS -N4 -RTS
.\.build\lab2.exe list lab2/demo.hfar
.\.build\lab2.exe unpack lab2/demo.hfar lab2/restored
node scripts/benchmark.mjs
```

Збирання обов’язково використовує `-O2 -threaded -rtsopts`. Кількість працівників — аргумент `pack`; `+RTS -N4` дозволяє одночасне виконання на чотирьох ядрах. Пул містить не більше заданої кількості працівників. Архіватор паралелить файли; для одного великого файла прискорення між файлами відсутнє.

Усі файли містяться в одному власному архіві `.hfar`, кожен зі своєю частотною таблицею. Підтримано порожні файли, один унікальний байт, двійкові дані й Unicode-назви. Відновлені дані перевіряються за CRC32. Імена з різних директорій мають бути різними без урахування регістру. Існуючі результати не перезаписуються. Максимум: 10000 файлів, 512 МіБ на файл; файли завантажуються до пам’яті, тож доступна RAM також обмежує розмір набору.

Результати: [CSV](benchmark.csv), [журнал](../verification/benchmark.txt). Звіт: [PDF](report.pdf), [DOCX](report.docx), [Markdown](report.md).

## Формат HFAR v1

Числа зберігаються в big-endian. Заголовок: байти `HFAR`, версія `01`, `Word32` кількість файлів. Для кожного файла:

| Поле | Формат |
| --- | --- |
| Довжина імені та ім’я | Word16; UTF-8 байти |
| Початковий розмір | Word64 |
| Кількість різних байтів | Word16, 0..256 |
| Частотна таблиця | Пари Word8 + Word64, за зростанням байта |
| Кількість значущих бітів | Word64 |
| CRC32 вихідних даних | Word32, IEEE CRC32 |
| Стиснені дані | ceil(bits / 8) байтів, перший біт старший |

Дерево відновлюється детерміновано: вузли впорядковано за частотою, потім найменшим символом піддерева; зливаються два найменші. Для одного символу код має довжину нуль: кількість повторень відома з початкового розміру. Невикористані молодші біти останнього байта нульові.

Малі файли та дані з рівномірним розподілом можуть дати архів більший за оригінал через заголовки й частотні таблиці. Це очікувана властивість формату.
